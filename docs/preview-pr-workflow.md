# Create a Preview Pull Request

The preview workflow only runs for pull requests. Pushing a branch by itself is not enough.

For this fork, the pull request must target:

```text
D-artisan/k8s-preview:main
```

Do not open the preview PR against `araminian/k8s-preview`, because the local Argo CD ApplicationSet is configured to watch `D-artisan/k8s-preview`.

## 1. Start from the latest main branch

```bash
git checkout main
git pull origin main
```

## 2. Create a feature branch

Use a descriptive branch name:

```bash
git checkout -b feature/test-preview
```

## 3. Make and commit your change

After editing the application:

```bash
git add .
git commit -m "Test preview environment"
```

## 4. Push the feature branch to your fork

```bash
git push -u origin feature/test-preview
```

## 5. Create the PR against your fork's main branch

Using GitHub CLI:

```bash
gh pr create \
  --repo D-artisan/k8s-preview \
  --base main \
  --head feature/test-preview \
  --title "Test preview"
```

Verify that the PR exists in the correct repository:

```bash
gh pr list --repo D-artisan/k8s-preview
```

The PR should show:

```text
feature/test-preview -> main
```

inside `D-artisan/k8s-preview`.

## 6. Watch the preview workflow

Opening the PR triggers `.github/workflows/ci-preview.yaml`.

The expected flow is:

```text
PR opened
  -> GitHub Actions builds and pushes the image
  -> preview-<PR_NUMBER> branch is created
  -> the PR receives the preview label
  -> Argo CD ApplicationSet detects the PR
  -> todo-app-preview-<PR_NUMBER> Application is created
```

Check the workflow from GitHub, or with:

```bash
gh run list --repo D-artisan/k8s-preview
```

## 7. Verify Argo CD discovers the PR

The ApplicationSet polls GitHub, so allow up to about 90 seconds after the workflow adds the `preview` label.

```bash
kubectl get applicationsets -n argocd
kubectl get applications -n argocd -w
```

You should eventually see an Application similar to:

```text
todo-app-preview-<PR_NUMBER>
```

## 8. Verify the Istio ingress

Before the preview Application exists, this can return `404`, which is expected:

```bash
curl -I http://localhost:30080
```

Once the preview resources are deployed, use the PR URL generated by the workflow rather than requesting the ingress root directly.
