# KEDA and Scale-to-Zero

## What KEDA does

KEDA changes the number of replicas according to demand.

This project uses the KEDA HTTP Add-on so an idle preview application can scale to zero Pods and wake up when HTTP traffic arrives.

## Install KEDA and the HTTP Add-on

Install these before asking Argo CD to sync preview resources:

```bash
make install-keda
make install-keda-http-addon
```

Verify:

```bash
kubectl get pods -n keda
kubectl get pods -n keda-http-addon
```

## HTTPScaledObject

The preview manifest contains:

```text
HTTPScaledObject/preview-todo-app
```

Check that Kubernetes knows this custom resource:

```bash
kubectl get crd httpscaledobjects.http.keda.sh
kubectl api-resources --api-group=http.keda.sh
```

Inspect a preview:

```bash
kubectl get httpscaledobject -n preview-2-todo-app
kubectl describe httpscaledobject preview-todo-app -n preview-2-todo-app
```

## Why there may be no Pods

The preview configuration allows:

```text
minimum replicas: 0
maximum replicas: 2
```

So this can be healthy:

```bash
kubectl get deployment -n preview-2-todo-app
# READY 0/0

kubectl get pods -n preview-2-todo-app
# No resources found
```

The important distinction is:

```text
Service + Deployment + HTTPScaledObject exist, but Pods = 0
    -> expected scale-to-zero

Namespace/resources do not exist at all
    -> deployment/sync problem
```

## Request flow from zero

```text
HTTP request
  -> Istio
  -> KEDA HTTP interceptor
  -> KEDA scales Deployment up
  -> Pod becomes Ready
  -> request is forwarded
```

Watch it happen:

```bash
kubectl get pods -n preview-2-todo-app -w
```

Then request the PR URL generated by GitHub Actions.
