# Troubleshooting Runbook

## No Application appears in Argo CD

Check that the PR is open in the correct repository:

```bash
gh pr list --repo D-artisan/k8s-preview
```

Check the PR has the `preview` label:

```bash
gh pr view   --repo D-artisan/k8s-preview   --json number,state,labels,headRefName,baseRefName
```

Check the ApplicationSet:

```bash
kubectl get applicationsets -n argocd
kubectl describe applicationset todo-app-preview-environment -n argocd
```

Check generated Applications:

```bash
kubectl get applications -n argocd
```

Remember: a branch push alone does not create the preview. The workflow is triggered by pull request events.

## Application exists but says Missing / OutOfSync

Get the exact Argo CD error:

```bash
kubectl -n argocd get application todo-app-preview-2   -o jsonpath='{.status.operationState.message}{"\n"}'
```

Check conditions:

```bash
kubectl -n argocd get application todo-app-preview-2   -o jsonpath='{range .status.conditions[*]}{.type}{": "}{.message}{"\n"}{end}'
```

## Error: http.keda.sh/v1alpha1 not found

This means Argo CD attempted to deploy `HTTPScaledObject` before the KEDA HTTP Add-on CRD was available.

Install and verify:

```bash
make install-keda
make install-keda-http-addon

kubectl get pods -n keda
kubectl get pods -n keda-http-addon
kubectl get crd httpscaledobjects.http.keda.sh
kubectl api-resources --api-group=http.keda.sh
```

Then hard-refresh the Application:

```bash
kubectl annotate application todo-app-preview-2   -n argocd   argocd.argoproj.io/refresh=hard   --overwrite
```

Retry the sync in the Argo CD UI with:

```text
REFRESH -> Hard Refresh
SYNC -> SYNCHRONIZE
```

## Namespace not found

Use the preview namespace naming convention:

```text
preview-<PR_NUMBER>-todo-app
```

For PR 2:

```bash
kubectl get all -n preview-2-todo-app
```

The Argo CD Application name `todo-app-preview-2` is not the namespace name.

## No Pods are present

First check whether the other resources exist:

```bash
kubectl get all -n preview-2-todo-app
kubectl get httpscaledobject -n preview-2-todo-app
```

If the Deployment exists with zero replicas and the HTTPScaledObject is Ready, this is expected KEDA scale-to-zero behavior.

## localhost:30080 returns 404

Check:

```bash
curl -I http://localhost:30080
```

A response from `istio-envoy` with `404 Not Found` means Istio is reachable but no route matched the plain localhost host.

Use the PR URL generated by GitHub Actions.

## Argo CD UI port is already in use

Find the process:

```bash
sudo lsof -i :8085
```

or:

```bash
ss -ltnp | grep :8085
```

You can choose another local port manually:

```bash
kubectl port-forward svc/argocd-server -n argocd 8086:443
```

Then open:

```text
https://localhost:8086
```
